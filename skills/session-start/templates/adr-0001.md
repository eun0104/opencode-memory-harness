# 0001. Record decisions as ADRs

- Status: accepted
- Date: YYYY-MM-DD
- Source: harness setup

## Context

Decisions and rejected alternatives live in the conversation where they were made, and that
conversation is compacted or ends. Without a durable record, a later session proposes a rejected
approach again, confidently.

## Decision

Every choice between alternatives that should outlive the current branch gets one file,
`docs/adr/NNNN-<slug>.md`, numbered in sequence, with the sections of this file:

- **Status**: `proposed`, `accepted`, or `superseded by NNNN`.
- **Source**: where the decision is evidenced: planning session, commit, data file, or paper.
  Record only what was said or observed; never an inference.
- **Alternatives considered**: each rejected option with the reason. This is the part a later
  session needs most.

After acceptance, only the status line changes. A changed decision gets a new ADR that
supersedes the old one.

## Alternatives considered

- Notes in a handoff file — rejected: prose written by the agent about its own progress drifts,
  and whatever is only in the conversation is lost at compaction.

## Consequences

Loosening a gate test's assertion or tolerance is a decision and needs an ADR here first.
